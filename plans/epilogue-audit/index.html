The visual-system contract

Every future executor must treat this section as a hard boundary, not a preference.

Protected, no autonomous edits

  • All Metal files under Core/Shaders and Core/Background/Shaders.
  • BookAtmosphericGradientView, FluidAmbientGradientView, UnifiedAtmosphericGradient, and their renderer/config inputs.
  • OKLABColorExtractor, atmosphere extraction, palette conversion, enhancement values, and color-selection behavior.
  • Glass modifier order, shapes, tint values, masks, overlays, clips, and material layering.
  • Typography choices, spacing tokens, book-cover geometry, motion curves, animation durations, and shader-fed geometry.
  • The existing user change in BookConnectionsCard.swift.

What a safe fix is allowed to do

  • Correct state, identity, validation, persistence, routing, security, and error reporting.
  • Add tests and deterministic fixtures without changing production pixels.
  • Fix compiler-confirmed API incompatibilities in place, preserving modifier position and expression.
  • Touch layout only after baseline capture and explicit design approval.
  • Stop immediately if a nonvisual fix requires changing a protected path.

Execution plan

Order matters. Each phase reduces the risk of the next one. No phase authorizes source changes by itself.

Phase

Freeze and fingerprint the visual system

Record the exact working diff, preserve the existing BookConnectionsCard.swift edit, and fingerprint every protected path before implementation.

  1. Record git status --short, git diff --stat, and the current commit.
  2. Hash the shader, background, color, and design-system files. Store hashes only in the implementation worktree or review artifact.
  3. After the build baseline works, capture deterministic Book View, Ambient, completion, session, and gradient states on fixed simulator devices.
Gate: No protected file is modified. No pre-existing user diff is overwritten.
Phase

Restore a trustworthy Xcode 27 baseline

Fix only the configuration, target, import, version, and dependency issues required to build and test.

  1. Commit a nonsecret base xcconfig and keep secrets in an untracked override. Remove the xcconfig from the app Resources phase through Xcode.
  2. Add the missing SwiftData import at TrailMarkerViews.swift.
  3. Repair the unit-test host, module name, target membership, and shared schemes through Xcode. Never edit project.pbxproj by hand.
  4. Align app and widget version/build numbers. Remove the unused WhisperKit CLI product and pin the library to a reviewed revision or release.
  5. Run a clean SDK 27 build and tests from a deterministic simulator destination.
No Book View layoutNo gradientsNo shadersNo glass chains
Gate: Clean build exits 0. Test-host smoke test launches. Production UI source is unchanged except the single missing import.
Phase

Stop data loss before fixing polish

Persistence recovery is the most dangerous part of the codebase. Fix it before state or UI work.

  1. Replace automatic SwiftData store deletion with quarantine, backup, diagnostic, retry, and explicit reset.
  2. Prevent writes when only an emergency in-memory container is available. Present a recovery state with retry and export.
  3. Use one canonical V10 schema and EpilogueMigrationPlan. Include the knowledge-graph models used at launch.
  4. Create historical persistent-store fixtures. Test every schema hop, relationship, identifier, rollback, and failure path.
Gate: Failure injection never deletes the source store. No editable app opens on an ephemeral store. Historical fixtures migrate with unchanged record counts and relationships.
Phase

Repair Book View state and session integrity

Correct data flow without restructuring the view hierarchy.

  1. Create canonical identity helpers for books, sessions, notes, quotes, replacement, and Ambient persistence.
  2. Make Book Detail read mutable state from one observable canonical model while retaining the exact view tree and modifier order.
  3. Centralize page parsing and validation. Write the same accepted page to every record and define unknown-page-count behavior.
  4. Cancel delayed completion work, preserve the stop timestamp, report save failures, restore or close unfinished sessions, and prevent duplicate archive records.
  5. Wire the re-entry Ambient action and Add Page Count action. Persist or remove completion fields that currently discard input.
Gate: Unit and integration tests cover every item. Protected-file hashes remain identical. Same-state screenshots show no unintended pixel drift.
Phase

Close security and privacy gaps

Assume every shipped binary and tracked file is public.

  1. Rotate all committed credentials, remove them from the current tree and history, then add secret scanning.
  2. Replace extractable shared proxy authentication with server-validated short-lived authorization.
  3. Redact invitation tokens and deep-link query values. Enforce exact HTTPS host validation.
  4. Make Keychain writes and deletes return typed failures. Update UI state only after success.
  5. Centralize notification permission and request it in context. Remove unused photo-library permission strings through Xcode if production code does not need them.
Gate: Secret scan is clean, rotated values are invalid, URL validation tests pass, and permission prompts occur only from explicit user flows.
Phase

Fix performance and SDK 27 diagnostics one seam at a time

Do the nonvisual work first. Treat anything near color extraction or shader sizing as a separate design review.

  1. Keep slider updates in memory while dragging and persist once on completion. Do not fetch and rewrite the full library on every movement.
  2. Move launch maintenance off the interactive main-actor window and remove the memory-resurfacing N+1 queries.
  3. Remove or debug-gate unbounded cover-image retention. Preserve exact image and palette results.
  4. Resolve actor-isolation warnings in isolated service batches with targeted tests. Keep Swift 5 mode until the warning gate is clean.
  5. Fix only compiler-confirmed ContentBuilder ambiguities in place. Never reorder background, overlay, mask, clip, or glass modifiers.
Gate: Build warnings trend to zero, slider persistence is bounded, launch interaction remains smooth, and visual baselines remain unchanged.
Phase

Handle pixel-affecting Book View fixes with Kris in the loop

This phase is never autonomous. Make one narrowly scoped change, run it, compare it, and stop for review.

  1. End Session compact width and input validation.
  2. Active-session HUD compact behavior, live timer, and 44 by 44 point hit regions.
  3. Progress-artwork containment at 320 points and iPad split widths without touching its gradient or motion.
  4. Dynamic Type and collapsed-summary behavior while preserving the typographic character.
  5. Known background-before-glass violations, only after confirming the active path and an equivalent hit-testing solution.
  6. Toolbar constrained-width behavior using availability-gated SDK 27 APIs only if the current composition demonstrably fails.
Gate: Each change has same-device before and after screenshots, accessibility-size screenshots, and explicit visual approval. Any shader, gradient, color, glass, type, spacing, or motion drift causes immediate rollback.

Nonnegotiable stop rules

These are designed to prevent a repeat of the previous failure.

A protected file changes

Stop and report the exact dependency. Do not “make it work” by editing a shader, gradient, palette, glass chain, design token, or animation.

The hierarchy must change

Stop and request design approval. SwiftUI identity and geometry can alter shaders, glass, animation state, and composition even when the diff looks harmless.

A migration test loses or duplicates data

Stop. Preserve the source store and diagnostics. Never invoke automatic deletion as recovery.

A screenshot drifts outside the target area

Stop and roll back. There is no acceptable collateral visual change in this repair cycle.

The compiler suggests a broad modifier rewrite

Fix only the diagnosed expression in place. If that cannot compile without moving modifiers, stop for review.

The live source no longer matches this audit

Re-audit the affected path. Do not execute stale steps against changed state.

Considered and rejected

No shader rewrite, no gradient replacement, no “native cleanup.”

The custom atmosphere, OKLAB extraction, enhanced palette behavior, and Metal rendering are product decisions, not generic technical debt.

No BookDetailView decomposition during bug repair.

The file is too large, but extracting view bodies now can change identity, layout proposals, environment propagation, and animation behavior. Extract pure validation and persistence seams first, behind tests.

No broad Dynamic Type or toolbar restyle.

Accessibility and constrained-width failures are real. Their solution must preserve Epilogue’s typographic and spatial language, not replace it with a generic system composition.

No screenshots from the reverted build.

Those images document an implementation that changed the design and remain invalid. The screenshots in this report were recaptured from the restored Epilogue 1.9 simulator installation.
